# rootfs/ — our own root filesystem (p3) and the card image

Everything that builds the **root filesystem we boot instead of the vendor's Yocto 3.1.4**: a Buildroot
`BR2_EXTERNAL` tree, the overlay, and the card-image scripts (`build-rootfs.sh`, `check-rootfs.sh`,
`make-card-image.sh`). Device facts go in `SYSTEM_ANALYSIS.md`, open work in
`IMPROVEMENT_PLAN.md`; neither is restated here. The root filesystem is booted and working on `.188`; an image generated by `make-card-image.sh` on the earlier seven-partition layout booted `.115` on 2026-10-12 (operator-verified at the panel: launcher, touch calibration from the NOT CALIBRATED status, onboard-speaker sound, USB keyboard and pad, the Control Panel SSH page workflow; host name `arca-<4 hex>`). **The current three-partition layout boots from a flashed card:** `.115`, 128 GB, 2026-10-15, video-timed by the operator — `growroot` from 20 s to 2 m 40 s, the ed25519 key then instant (the grow fills the entropy pool [inferred]; on an 8 GB card the key took ~1 min, below), `udhcpc` 15 s with no lease while the cable was in (the lease came later in the background), launcher at 3 m 06 s; Information page and `arca-<4 hex>` name seen. With the injector's data side unplugged every app starts and the network apps report it (`No IPv4`, `eth0 DOWN`); plugging the cable back in recovers the network.

## Rules before the first edit

- **ABI: soft-float EABI (not EABIHF), loader `/lib/ld-linux.so.3`, glibc >= 2.31.** Measured 2026-10-08 by
  `readelf` of the vendor `libc.so.6` and `/opt/games/snake`: our dynamic binaries need at most `GLIBC_2.28`
  plus `libasound.so.2`, `libm`, `libstdc++`; BlueZ/bluealsa (`bluetooth/build-bluez.sh`, `build-bluealsa.sh`)
  also need glib, `libdbus-1.so.3` and readline 8. `vnc_client` and `devmem_write` are static hard-float.
- **Build: Buildroot 2025.02 LTS** (supported to 2028-03), out of tree in WSL's native fs (`~/`, not DrvFs).
  `BR2_cortex_a8` + `BR2_ARM_EABI` + NEON, internal glibc with C++, no kernel (`BR2_LINUX_KERNEL` off, 4.14
  headers), BusyBox init driving SysV `rcS.d`/`rc5.d` so provisioning's links run unchanged.
- ⚠️ **`BR2_PACKAGE_BASH` needs `BR2_PACKAGE_BUSYBOX_SHOW_OTHERS`; `make defconfig` drops it silently.**
  `build-rootfs.sh` gates it. Debootstrap is ruled out: no qemu-user/binfmt here, and generic ARMv7 packages
  may carry `sdiv` (Cortex-A8 has none). Gate the target tree with `native_apps/check-arm-safe.sh`.
- **The root is p3, the last partition, so it can grow** (`root=/dev/mmcblk0p3` is compiled into U-Boot; an older `u-boot.img` is refused by `arca_uboot_root_ok`). **The image carries nothing of the vendor's and is the same for every unit:**
  `make-card-image.sh` writes the partition table itself from `ARCA_LAYOUT` in `lib/arca-identify.sh` (p1 boot, p2 log 1 GiB, p3 root 512 MiB; identical on every
  card; `/home/root/data` is a plain directory on p3, so a reflash wipes it), formats p1 and puts on it only `MLO` (first), `u-boot.img`, `uImage-system`,
  `uImage-fallback` (a second copy of the same kernel) and `uEnv.txt`. Inputs are `--mlo`/`--uboot` (from `uboot/build.sh`) and `--kernel`
  (from `kernel/build-image.sh`): `SYSTEM_ANALYSIS.md#4-boot-chain-and-recovery`. Recovery is "reimage the card", and so is an upgrade: **units are re-flashed, never migrated** (operator ruling 2026-10-12), so nothing carries in-place upgrade code; a new kernel or new drivers ship as an image.
- **Our links:** `rcS.d` `S01mountall` `S01seedrng` `S02alignment` `S03udev` `S04hostname` `S05sysctl`
  `S04firstboot-hostname` `S06watchdog` `S07growroot` `S07syslog` `S08networking`; `rc5.d` `S02dbus-1` `S09sshd` `S20hwclock.sh` `S30avahi-daemon`
  (all linked by `rootfs/board/arca/post-build.sh`). `/usr/sbin/set-hostname` is an overlay file (`overlay/usr/sbin/set-hostname`, mode 0755 set by the
  same script). **sshd generates an ed25519 host key only** (`overlay/etc/init.d/sshd`; `post-build.sh` removes the
  RSA key and links ed25519 into `/home/root/data/ssh`, on p3): measured on `.188`, `ssh-keyscan` offers only `ssh-ed25519`, and the first-boot generation took
  ~1 min with `seedrng: uninitialized urandom read` in dmesg before `crng init done` — the wait is entropy [inferred].
- **The product name is `rootfs/board/arca/os-release`**, the one source for the device's `/etc/os-release`, `lib/product.sh` and `native_apps/common/product.c`. Buildroot's target-finalize writes its own (`NAME=Buildroot`) before it copies the overlay and runs the post-build hook (Makefile, 2025.02), so `post-build.sh` installs ours last; `check-rootfs.sh` refuses a tar that still says Buildroot. `ID=arca` stays an identifier.
- **The source offer (GPL-2.0 §3(a)):** `make-source-offer.sh` builds the offer tar outside the repo; `check-source-offer.sh` verifies it and maps every ELF, `.ko`
  and p1 file on an image to a source; `source-map.tsv` is that map for what Buildroot did not install (⚠️ **a new binary on the card needs a row there**, or the
  checker fails); `package-hashes/` replaces a package's own hash file. ⚠️ **A `.hash` under `BR2_GLOBAL_PATCH_DIR` does NOT fix the `linux-headers` `legal-info`
  abort**, because it is checked together with the stock file; `external.mk` overrides `LINUX_HEADERS_HASH_FILES` and `LINUX_HEADERS_LICENSE_FILES` instead, and
  `build-rootfs.sh` gates it (measured: the pre-change tree exits 2).

- **Root's login shell is `/bin/bash`**, set by `rootfs/board/arca/post-build.sh` (the Buildroot skeleton gives `/bin/sh`,
  BusyBox ash); the prompt comes from the overlay's `/etc/profile.d/prompt.sh`. Measured on `.188`.
- **`make-card-image.sh` installs every component offline by default** (`--bundle <b>`, else `build/release`; `--no-bundle` builds the bare base) (`rootfs/commission-offline.sh --base <tree>` against the new image's p3 and p2). Measured on `.188`: a card built that way boots to the launcher, touch works, and the launcher's Shutdown tile runs `poweroff` and the panel goes dark.
- **The image carries its licence documents:** `LICENSE.md`, `manifest.csv`, `licenses/` and `SOURCE-OFFER.txt` in p3 `/usr/share/doc/arca-licenses/` (`licence_docs_install`). `--legal-info` (default: `br-rw/legal-info` of the invoking user), `--source-tag` (default: the bundle's tag) and `--source-url` feed them; without a legal-info tree or a tag the summary prints `WARNING` lines and **that image must not be published**. Measured: a real image held all four, mode 0644, fsck clean.

## What the image must carry, and what it need not

- **Carry:** OpenSSH, not dropbear (the overlay's key-only `sshd_config` is the only sshd policy; `provision.sh` never edits it);
  a `/dev/watchdog` feeder on every boot (60 s); udev with the rule that makes
  `/dev/input/touchscreen0` (`app_launcher` exits without it); dbus (+ `DBUS_SYSTEM_BUS_ADDRESS`), avahi,
  `amixer`, `libasound` **with `/usr/share/alsa`**; `insmod`/`lsmod`, `rdate`, `hwclock -u`, `date -s`,
  `logger` + a syslogd, `start-stop-daemon`, `pidof -x`, `killall`, `/usr/share/zoneinfo`, DHCP on eth0
  sending the host name, `reboot`/`poweroff` (BusyBox has no `shutdown` applet).
- **Need not:** cron, `S40ctrlblk`, `update-rc.d`, any Steelcase software.
  BlueZ and bluealsa are our own builds, not Buildroot packages.

## Per-unit state (an image carries none)

**`make-card-image.sh` builds one generic image and refuses SSH key material in the rootfs tar, on p3 or from the bundle.** It also refuses a tar that fails `check-rootfs.sh`, before writing any image (measured: a tar older than the ed25519-only commit gives 48/1, "no ssh_host_rsa_key in the image", and is refused; the rebuilt tar gives 49/0). A unit's own
state travels only through the backup items (`lib/CLAUDE.md`, provision.sh step 0; `DEVELOPING.md#plug-in-file-formats`).
The unit names itself on first boot (`S04firstboot-hostname`: `arca-<4 hex>` from the kernel's random pool, applied with
`/usr/sbin/set-hostname`), and sshd generates its host key then; highscores, host keys (`/home/root/data/ssh`) and cron live under `/home/root/data` on p3, which
the image creates empty. ⚠️ **`config.c:65` saves by tmp + `rename()`, which replaces a
symlink instead of writing through it**, so a symlink farm onto another partition does not relocate that file. A fresh p3 means a slow first boot
(the vendor's keys are identical across units, `SYSTEM_ANALYSIS.md#52-as-we-run-it--game-mode`).

**`set-hostname` is the one writer of the name files.** It writes `/etc/hostname` and rewrites `/etc/hosts` so the unit's own name never sits
on a non-loopback line (it would resolve to a wrong address); it keys the `/etc/hosts` removal on the name it reads from `/etc/hostname`, never
a hardcoded one, and refuses to write an `/etc/hosts` that lost `localhost`. `S04firstboot-hostname` and `provision.sh --hostname` call the same
file, so they cannot drift; `/etc/hostname` is the only home of the name. NAME is one label (`rw09`, not `rw09.local`: mDNS appends `.local`).

## `commission-offline.sh`: the image step, not a user flow

`rootfs/commission-offline.sh --bundle <tar.gz|dir> --base <dir>` installs a release bundle and the provision plan into the partitions
`make-card-image.sh` mounted as `<base>/{root,log}`, which is its only caller. **It has no prompt, no clean and no disk scan:** it
reads no terminal, needs no root of its own, mounts nothing and never writes p1; `lib/arca-identify.sh` refuses a `root` that lacks our
marker. The retired flags (`--no-clean`, `--keep-<group>`, `--delete-factory`, `--unattended`, `--disk`, `--release`, `--ssh-auth=*`,
`--sshd-only`) are **refused by name with a non-zero exit** — a flag accepted and ignored reads as a choice honoured. Host name, password and
ssh identity are not set here. **It verifies what it installed, on the card:** md5 of every installed file against the bundle manifest; `+x`
(real ext4 honours it, so offline that check is a measurement and on `/mnt/c` it cannot be); `check-arm-safe.sh` over the downloaded binaries;
every `.app`'s `exec=`/`icon=` and that `default-app` names one; `dash -n` on every `/bin/sh` script it wrote. `make-card-image.sh` then runs `check-rootfs.sh --tree <base>/root`, which allows no dangling rc link: the tarball check lets one dangle only when a `provision-rules.conf` `install` record supplies its `/etc/init.d` target (the bluetooth stop link).

⚠️ Three ways that verification can lie, all guarded: `dash -n` misses bashisms (`[[` parses as a command name); a missing
`arm-linux-gnueabihf-objdump` is a **refusal**, not a pass, so the caller counts the ELF candidates itself and says what it did not check
(`--arm-check=skip` is the deliberate override); and a **stripped** binary cannot be gated, so the checker returns 2 ("could not judge") and the
installer proceeds with a loud block naming the count. `scummvm` and `vnc_client` ship stripped, so **every full bundle** takes that path — the
sound verdict is the build-time one, on the unstripped artifact. Regression: `tests/commission_offline_test.sh` (needs root and a staged
bundle; every check has a sabotage case); rules in `tests/CLAUDE.md`.
