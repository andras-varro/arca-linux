# rw20 U-Boot v2026.10 build (host side only; nothing installed, no device touched)

Base: pristine U-Boot tag v2026.10. Patch: `uboot/rw20-board.patch` (git diff vs the tag; `git apply --check` passes on a
pristine export) adds board `rw20` (`board/steelcase/rw20/`, `configs/rw20_defconfig`, `omap3-rw20.dts`). Defconfig: `rw20_defconfig`.

## Commands
    # host: Ubuntu 20.04 WSL; apt-get install gcc-10-arm-linux-gnueabihf (root) because stock gcc 9 is refused by U-Boot 2026.10 ("older than 10.0")
    # W = a scratch dir OUTSIDE the repo (e.g. ~/rw-uboot); UB = a pristine v2026.10 checkout
    mkdir -p $W/tc/bin   # symlink all /usr/bin/arm-linux-gnueabihf-* into $W/tc/bin, gcc->gcc-10, cpp->cpp-10
    cp -a $UB $W/u-boot && git -C $W/u-boot apply /mnt/c/work/roomwizard/uboot/rw20-board.patch
    export PATH=$W/tc/bin:$PATH
    make -C $W/u-boot rw20_defconfig O=../build
    make -C $W/u-boot O=../build -j8 CROSS_COMPILE=arm-linux-gnueabihf-
Outputs: MLO (49496 B), u-boot.img (422064 B), u-boot-spl.bin, .config. Build outputs are not committed.

## Which file the SPL loads
SPL (CONFIG_SPL_FS_FAT, SPL_MMC) mounts FAT partition 1 and reads u-boot.img (CONFIG_SPL_FS_LOAD_PAYLOAD_NAME), a legacy
uImage (load/entry 0x80100000) -- NOT u-boot.bin (raw, no header). p1 must hold: MLO, u-boot.img, uImage-system, uImage-fallback.
MLO = 512 B CHSETTINGS TOC + GP header (size word 0xbf58 incl. the header, load 0x40200800) + SPL; checked by hex/python parse. u-boot-spl.bin 48976 B, GP header size < 0xEC00 (the scratch area at 0x4020EC00 limits an SPL linked at 0x40200800 to 0xE400).
Partition 1 is an MBR partition: the defconfig must carry `CONFIG_DOS_PARTITION` (SPL gets `SPL_DOS_PARTITION` from it; without it `part_get_info(1)` finds no partition driver and the SPL cannot mount p1 [inferred from `disk/part.c`/`fs/fat/fat.c`, not run], `CMD_FAT` (the env's `fatload`) and `HUSH_PARSER` (the env's `if run ...; then`). `devkit8000_defconfig` gets all three from `CONFIG_DISTRO_DEFAULTS`, which `rw20_defconfig` does not set. Boot device: the SPL trusts the ROM-reported device (`save_omap_boot_params`, `boot-common.c`), which maps MMC1 to FS mode; ROM params outside SRAM 0x40208000-0x40210000 leave it `BOOT_DEVICE_NONE` and the SPL tries nothing.

## Value sources
- SDRC MCFG_0 0x03588099, ACTIM_A 0x7AE1B4C6, ACTIM_B 0x00024217, RFR_CTRL 0x0005E601, MR 0x32: read from the live unit's SDRC registers.
  Hardcoded in rw20.c get_board_mem_timings(); the four words found in u-boot-spl.bin. CS1 handling = mainline omap3/sdrc.c.
- Pinmux: `rw20-mux.h` = all 152 words of the live padconf dump (0x48002030-0x48002264, 0x48002A00-0x48002A24, .188, 2026-10-09),
  generated by `uboot/gen-mux.py` (run from the scratch dir; it reads the U-Boot tree's `mux.h` and the padconf dump named as its argument); replayed as 32-bit writes in set_muxconf_regs().
- Console UART2 (stdout-path=&uart2, SPL and U-Boot, DM serial). Pads 0x216C-0x2172 come from the dump (mode 1).
- Env/bootargs: `SYSTEM_ANALYSIS.md` 4.4 sysargs verbatim; bootdelay=1; loadaddr 0x82000000; ATAG trio; prompt "arca # ".
- preboot = run uenv (`CONFIG_USE_PREBOOT` + `CONFIG_PREBOOT`; `main_loop()` runs it before `bootdelay_process()` [read in `common/main.c`]): imports the optional `uEnv.txt`, see "uEnv.txt" below.
- bootcmd = run rwboot: mmc dev/rescan; fatload ${kernel} (uImage-system) && sysboot; else fatload ${fallback} (uImage-fallback) && sysboot. ENV_IS_NOWHERE.
  `CONFIG_BOOTCOMMAND` is compiled in only with `CONFIG_USE_BOOTCOMMAND=y` (the defconfig carries both): with the string alone, `.config` drops it
  and the default env has no `bootcmd` at all [measured: no `bootcmd=` in the `u-boot.bin` of the build before this fix], so autoboot ends at the prompt.
  The needed commands are all on: CMD_BOOTM + LEGACY_IMAGE_FORMAT, CMD_FAT, CMD_MMC, CMD_MEMORY (`mw.l`, `mw.b`), CMD_SLEEP (fractional), CMD_RUN, CMD_IMPORTENV, HUSH_PARSER (`if`, `while`, `&&`, `test -e`), ATAG trio.
- twl4030_power_init() in misc_init_r (full U-Boot only); twl4030_power_mmc_init(0) via board_mmc_power_init (VMMC1 3.15 V).

## Assumptions (inferred)
- vram=12M and mpurate=auto (4.4 shows the variables unexpanded); sysroot/sysrootfstype from 4.4.
- Live padconf was read AFTER Linux booted, so it may include kernel pinctrl changes, not only what the vendor U-Boot set.
- bi_arch_number = MACH_TYPE_OVERO (Overo lineage); ignored by the DT/appended-DTB kernel (inferred).
- SPL load address 0x40200800 (the vendor MLO's); mainline default 0x40200000 is not used.
- No board_boot_order: ROM-reported boot device is trusted (assumed MMC1 after the redirector warm reset).
- gpmc_init() kept as devkit8000 does; GPMC live dump not replayed (inferred unnecessary: kernel DT programs GPMC).
- Watchdog, PLL/clock: mainline prcm_init for 13 MHz sys_clk; resulting MPU/L3 rates NOT compared to the live 600/166 MHz (compare after boot).
- U-Boot DTS (omap3-rw20.dts) hand-written: 256 MB, i2c1+twl4030, mmc1 4-bit; EFI capsule tool, DISPLAY_BOARDINFO, SPL_NAND disabled to build.
- fatload of uImage-fallback: bootm returns on CRC failure so fallback runs (not tested).

## Boot-progress LEDs
The patch drives the side LEDs as a permanent boot-progress indicator (no serial, no I2C, no SDRAM needed). Steady colour = working on
that stage, or hung there; blinking = a failure the code detected. SPL_TEXT_BASE is 0x40200800 (the vendor's load address;
`CONFIG_SPL_TEXT_BASE` in the defconfig). Nothing is installed by this build.
- The two side LEDs are SoC GPTimer PWM pads: red MCSPI2_SOMI 0x480021DA (GPT10), green MCSPI2_CS0 0x480021DC (GPT11), normally mode 1
  [measured on the running unit]. The code sets both to mode 4 (gpio_180 / gpio_181 = GPIO6 bits 20 / 21, active high) with 16-bit writes
  (`OMAP34XX_CTRL_BASE` 0x48002000 + `CP(MCSPI2_SOMI/CS0)` 0x1DA/0x1DC of `arch-omap3/mux.h`, read from the tree), clears OE (+0x34) and writes
  SETDATAOUT (+0x94) / CLEARDATAOUT (+0x90) of `OMAP34XX_GPIO6_BASE` 0x49058000. GPIO6 access bus-faults without
  CM_FCLKEN_PER 0x48005000 / CM_ICLKEN_PER 0x48005010 bit 17 (EN_GPIO6; `PRCM_BASE` 0x48004000 + `struct prcm` 0x1000/0x1010), set first.
  Red lit from Linux with this exact sequence [measured]; green (bit 21) is inferred by symmetry. Code: `rw20.c` rw20_gpio6_enable / rw20_led(red, green) / rw20_boot_stage.
- Stages (`rw20_boot_stage`): 1 = end of `s_init`, in the SPL and again in U-Boot proper (after the padconf replay, prcm_init and per_clocks_enable): red.
  2 = SPL `board_init_f` after omap3_mem_init(), only if a write/readback of 8 words at 0x80300000/0x84000000/0x88000000/0x8FF00000 passes: red + green.
  3 = SPL `spl_board_prepare_for_boot()` (directly before `jump_to_image`): green. U-Boot proper: 4 = `board_init()` (after relocation and DM): red + green.
  5 = `board_late_init()` (after `initr_mmc`, `initr_env`, `misc_init_r` = twl4030_power_init, before preboot and bootdelay): green.
  Then the preboot/`rwboot` env scripts drive GPIO6 with `mw.l` on SETDATAOUT 0x49058094 / CLEARDATAOUT 0x49058090 (`CONFIG_CMD_GPIO` is off;
  variables `ledoff`, `ledred`, `ledgreen`, `ledyellow`, `redx3`, `greenx3`, `yellowblink` in `include/configs/rw20.h`): `ledoff` after `mmc dev`/`mmc rescan`;
  `redx3` after a successful `fatload`; `greenx3` in `sysboot`, right before `bootm` (x3 = off, on, off, on, off, on at 0.1 s steps, ending lit);
  `yellowblink` at the very end (both loads failed or `bootm` returned both times).
- Failure blink: `hang()` (`lib/hang.c`, hook before its `puts`, so it never returns; compiled for `CONFIG_TARGET_RW20`, SPL and proper) blinks red at 2 Hz forever.
  It times from the SoC 32 kHz sync counter (0x48320010, which `prcm_init` already reads in `s_init` [read in `clock.c`]), not `udelay()`: the GPTimer behind
  `udelay()` is not started in the early SPL [inferred from `omap-common/timer.c`, not run], and a `udelay` on a stopped timer never returns. A counter that does not move
  falls back to a spin cap (rate unknown) [inferred]. `yellowblink` loops `while run ledyellow && sleep 0.25 && run ledoff && sleep 0.25`; Ctrl-C makes `sleep`
  fail, ends the loop and leaves yellow steady at the `arca # ` prompt [measured in a sandbox build with a pty feeding ^C, not on the device's UART].
- Reading the panel (in order of appearance):
  | LED | meaning |
  |---|---|
  | dark from the start | SPL never reached its `s_init` |
  | red, then red + green | SPL got through SDRAM; stays red = SDRAM test failed |
  | red + green steady | SPL stuck before its jump hook (loading u-boot.img, or an SPL exception: `vectors.S` loops in place) |
  | red blinking, 2 Hz | `hang()`: an SPL failure (it is reached by every SPL failure path) or a U-Boot proper failure; the serial console has the reason |
  | green (SPL's last), then red | proper stuck between its `s_init` and `board_init` (relocation, DM, timer, dram_init, serial) |
  | red + green (proper) | `board_init` reached; stuck before `board_late_init` (MMC init with the twl4030 VMMC1 write, env, `misc_init_r`) |
  | green | `board_late_init` reached: preboot, the bootdelay second, or no bootcmd, or `mmc dev`/`mmc rescan` hung |
  | dark | `rwboot` passed `mmc rescan`; `fatload` of the kernel (or the fallback) failed or hung (also dark for the seconds a 5 MB load takes) |
  | red x3 | `fatload` succeeded, `sysargs` running |
  | green x3 | `bootm` reached. Still green = `bootm` hung or the kernel died before touching the pads; dark/other = the kernel took over the pads [inferred]; dark again then red x3 = `bootm` returned (bad image) and the fallback ran |
  | yellow blinking, 2 Hz | `rwboot` ran to its end: nothing booted. Ctrl-C on the serial console stops it at the prompt (yellow steady) |
  A frozen flash sequence (stuck dark in the middle of it) means `sleep` hangs, i.e. the timer is dead [inferred]. The vendor yellow LEDs come from the vendor's own U-Boot, not from this build.

## uEnv.txt
`uboot/uEnv.txt` is an all-commented template for an optional file of the same name in the root of FAT p1 (BeagleBone convention: plain `name=value` lines).
Missing or empty = the built-in defaults, silently: `test -e` guards the load, so no error text [measured in a sandbox build, with a FAT image]. `bootargs` replaces the built-in
`sysargs` command line, `optargs` is appended to either, `kernel` / `fallback` (defaults `uImage-system` / `uImage-fallback`) name the images, `bootdelay` takes effect because
preboot runs first [`common/main.c`]. Mechanism, all of it in `include/configs/rw20.h`: `uenv` fills 4 KB at `loadaddr` with newlines (`himport_r` with `-r` leaves old bytes behind the
data, so a last line without a newline gained a copy of its own tail [measured]), `fatload`s the file over it and runs `env import -r -t <loadaddr> 0x1000 bootargs optargs kernel fallback bootdelay`
(only those names are taken; any other line is ignored [measured]; `#` lines, blank lines and CRLF are handled [`lib/hashtable.c`, measured]). `userargs` holds the file's `bootargs` because `sysboot` can run twice
(`kernel` then `fallback`). A file over about 2 KB is cut. Tested only in a sandbox build [`sandbox_defconfig`, host gcc-10, scripts translated `mmc` to `host`], not on the unit.

- GP header variants: MLO = 512 B CH TOC, then the GP header (size word at 0x200, load address at 0x204). Ours holds the size INCLUDING the
  8-byte header (0xbf58 = file - 512); the vendor's EXCLUDES it (0xc298 = file - 512 - 8). Vendor-style MLO: write `size - 8` as a
  little-endian 32-bit word at offset 0x200 of a copy of the MLO; nothing else differs.
- Checks: GP header size <= 0xEC00 and load 0x40200800; sdiv/udiv 0 in `spl/u-boot-spl` and `u-boot` (`objdump -d | grep -cE '\s(s|u)div\s'`);
  `git apply --check` of the patch on a pristine tag export; `part_get_info_dos` present in `spl/u-boot-spl.sym`.
